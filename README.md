### Запуск приложения

Запуск приложения из корня проекта:

```
docker compose up -d --build
```

При первом запуске приложения создаются две таблицы `tasks` и `users` и добавляются данные (два пользователя и три задачи) из файла `init.sql`

| Пользователи из файла `init.sql` | Пароль      | Роль  |
| -------------------------------- | ----------- | ----- |
| test_1                           | password123 | ADMIN |
| test_2                           | qwerty      | USER  |

### Возможности

#### Пользователи

В этой реализации TaskManager можно зарегистрировать пользователя (роль будет USER). Регистрация с ролью ADMIN не предусмотрена (единственный админ добавлен в базу при ее создании username= test_1,  password = password123).

При входе пользователя в систему ему выдается токен JWT, который используется для всех ручек UserController и TaskController, а также для части ручек метрик (в запросах передаем Authorization: Bearer).

Пользователям с ролью USER доступны все методы в UserController и все методы в TaskController, кроме метода удаления задачи. Удаление задачи доступно только роли ADMIN.

Смена пароля или username у уже зарегистрированного пользователя не реализована.
#### Задачи

Цикл задач состоит из 3-х статусов: CREATED, IN_PROGRESS, DONE.

Задачу можно **создать** (status CREATED), при создании заполняется только description, исполнитель обязательно null, а автор задачи берется из запроса.

Задачу можно **изменить** (при изменении задачи фиксируется кто, когда и в какое поле внес изменение):
- Задачу можно взять в работу (status IN_PROGRESS), при этом обязательно указать исполнителя.
- Задачу можно завершить (status DONE), у завершенной задачи обязателен исполнитель. Завершить задачу можно только из статуса IN_PROGRESS.
- Можно вернуть задачу в созданные, при этом исполнитель выставляется null.
- Можно поменять описание задачи
- Можно поменять исполнителя задачи

Можно **удалить** задачу в любом статусе, доступно только роли Admin (задача просто не видна при запросах, из базы не удаляется). При этом исполнитель выставляется в null.

#### Фильтрация

Доступна фильтрация пользователей и задач.

Пользователи:
- Получить всех пользователей
- Получить пользователей у которых есть созданные задачи (где они авторы)
- Получить автора конкретной задачи
- Получить пользователей без созданных задач (нет авторства ни в одной из задач)
- Получить пользователей у которых есть назначенные задачи (где они исполнители)
- Получить исполнителя конкретной задачи
- Получить пользователей у которых нет назначенных задач (не являются исполнителем ни в одной из задач)
- Получить исполнителей задач, у которых задача находится в определенном статусе (в данной реализации либо в IN_PROGRESS либо в DONE)
- Найти пользователя по username

Задачи:
- Найти задачи конкретного автора
- Найти задачи конкретного исполнителя
- Найти задачи без исполнителя
- Найти задачи по статусу
- Найти задачи по дате создания
- Найти задачи по дате изменения (учитывается изменение полей описания, исполнителя и статуса задачи)
- Найти задачи по дате завершения
- Найти задачи по описанию

#### Мониторинг и логирование

Можно посмотреть данные о приложении через актуатор (health, metrics, info, ручки доступны metrics и info только роли ADMIN), прометеус, а также в графане (источник данных - прометеус). На проекте добавлены две кастомные метрики (`tasks.created` и `users.login.success`), для которых настроен дашборд в графане.

Логи пишутся в файл s`pring-boot-app.log`. Для работы с логами подключен ELK-стек (Elasticsearch, Logstash и Kibana).
